# Deployment (closed beta)

This app is **two deployables**, not one:

| Part | What | Where |
|------|------|-------|
| Frontend | Next.js (App Router) in `frontend/` | **Vercel** |
| Backend | FastAPI + the `full_auto` search engine | **Render / Fly / Railway / a VM** (NOT Vercel) |

### Why the backend can't go on Vercel
Vercel functions are request-scoped, time-limited, and run on an ephemeral
read-only filesystem. This backend needs the opposite of all three:
- **Headless Chromium** (Playwright / Crawl4AI) for full-page scraping.
- **Long-running in-process background search tasks** that outlive the HTTP
  request and are polled via `/search/status`.
- **A stateful database** on a writable disk (SQLite by default), plus the ATS
  seed done at startup.

So Vercel hosts the frontend; the backend runs on a persistent host.

---

## 1. Backend

A `Dockerfile`, `.dockerignore`, and `render.yaml` are included. Render is the
quickest path, but the Dockerfile runs anywhere (Fly.io, Railway, a VM).

### On Render (blueprint)
1. Push the repo to GitHub, then in Render: **New → Blueprint** and point it at
   the repo. It reads `render.yaml` (Docker web service + a 1 GB disk for SQLite).
2. Set the `sync: false` env vars in the dashboard (they're intentionally not in
   the file):
   - `FRONTEND_ORIGINS` — your Vercel URL(s), comma-separated, e.g.
     `https://four-in-a-thousand.vercel.app` (no trailing slash).
   - Engine API keys: `OPENAI_API_KEY`, `REED_API_KEY`, `ADZUNA_APP_ID`,
     `ADZUNA_APP_KEY`, `SERPER_DEV_API_KEY`, `SERPAPI_KEY`, `RAPIDAPI_KEY`,
     `CAREERJET_AFFID`, `CAREERJET_REFERER` (copy from your local `.env`).
   - `AUTH_SECRET` and `ADMIN_TOKEN` are auto-generated by the blueprint. If you
     set them by hand instead, use long random values.
3. Deploy. Health check is `GET /health`.

### Database: SQLite disk vs Postgres
- **Default (SQLite on a disk):** `render.yaml` mounts a disk and points
  `DATABASE_URL` at `sqlite:////app/backend/data/jobmatch.db`. Fine for a small
  beta. Note a single disk = a single instance (don't scale to >1 web instance).
- **Postgres (recommended if the beta grows / you want >1 instance):**
  1. Create a managed Postgres, set `DATABASE_URL` to
     `postgresql+psycopg://USER:PASS@HOST:5432/DBNAME`, and remove the disk.
  2. Add a driver to `backend/requirements.txt`: `psycopg[binary]`.
  3. The SQLite-only `PRAGMA`/`busy_timeout` code in `database.py` is already
     URL-gated, so it no-ops on Postgres. Schema is created by
     `init_db()`/`create_all` on boot. Caveat: `_migrate_columns()` is a
     hand-rolled `ALTER TABLE ADD COLUMN` helper written for SQLite; the adds it
     performs are valid Postgres too, but there's no Alembic — a fresh Postgres
     just gets the full current schema from `create_all`, which is what a new
     beta wants.

### Seed the 50 beta logins
Run `scripts/gen_beta_users.py` **against the deployed database** so the accounts
land where the app reads them:
- **Postgres:** run locally with `DATABASE_URL` set to the prod Postgres URL:
  `DATABASE_URL=postgresql+psycopg://... venv/Scripts/python scripts/gen_beta_users.py`
- **SQLite-on-disk:** run it in the host's shell (Render → Shell) so it writes to
  the mounted disk: `python scripts/gen_beta_users.py`. It also writes
  `beta_credentials.txt` (plaintext, gitignored) — copy it out, hand out the
  logins, then delete it from the server.

### Reset to a fresh landing state
`scripts/reset_user_data.py` clears all user/profile data but keeps the
user-independent embedding cache and the ATS store. Run it the same way (with the
right `DATABASE_URL`). See its `--help`.

### Owner analytics
`GET /admin/analytics` with header `X-Admin-Token: <ADMIN_TOKEN>` returns per-user
usage (logins, searches, ticks/crosses/applies, last-active). It's the only way
to read the `event_log`; it's locked (403) if `ADMIN_TOKEN` is unset.

## 2. Frontend (Vercel)

1. Vercel → **New Project** → import the repo, set **Root Directory = `frontend`**
   (Vercel auto-detects Next.js).
2. Set env var `NEXT_PUBLIC_API_URL` to the backend URL from step 1
   (e.g. `https://four-in-a-thousand-api.onrender.com`), no trailing slash.
3. Deploy. Then make sure the backend's `FRONTEND_ORIGINS` includes this Vercel
   origin (CORS), and redeploy the backend if you changed it.

## Env var reference (backend)
Required: `OPENAI_API_KEY`, `AUTH_SECRET`, `FRONTEND_ORIGINS`, `DATABASE_URL`.
Auth/analytics: `AUTH_SECRET`, `ADMIN_TOKEN`, `TOKEN_MAX_AGE_SECONDS` (optional,
default 30 days). Board sources: `REED_API_KEY`, `ADZUNA_APP_ID`,
`ADZUNA_APP_KEY`, `SERPER_DEV_API_KEY`, `SERPAPI_KEY`, `RAPIDAPI_KEY`,
`CAREERJET_AFFID`, `CAREERJET_REFERER`. Tuning knobs (all optional, have
defaults): `MAX_SEARCHES_PER_DAY`, `REED_PAGES_PER_TERM`, `ADZUNA_PAGES_PER_TERM`,
`DISCOVERY_ATS_CACHE_TTL_HOURS`, `STRONG_MODEL`/`MID_MODEL`/`CHEAP_MODEL`, etc.
(see `backend/app/config.py` and the top of `full_auto.py`).
